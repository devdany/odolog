## 1.
■ 계기판이 직접 쓰는 법인차 운행기록부
시동부터 시동을 끌 때까지 차량이 계기판 거리로 업무용승용차 운행기록부를 자동 작성하고, 운전자는 PIN으로 본인임을 확인한 뒤 내리기 전 한 번만 탭하면 되는 Pleos Connect 법인차 운행기록 앱입니다.

## 2.
■ 주목한 순간: "어제 몇 km 탔더라?" — 연말에 몰아 쓰는 운행일지

법인·복식부기 사업자의 업무용승용차는 관련비용(감가상각·리스료·유류비·보험료 등)이 연 1,500만원을 넘으면 국세청 양식의 운행기록부로 업무사용비율(업무용 사용거리 ÷ 총 주행거리)을 증명해야 비용으로 인정받습니다(법인세법 제27조의2, 시행령 제50조의2). 기록이 없으면 1,500만원 초과분은 비용에서 제외되고, 업무 외 사용분은 사용자 상여로 처분되어 법인세와 소득세를 이중으로 부담합니다.

그러나 2017~2021년 신고된 업무용승용차 419.8만 대 중 39.6%(166.3만 대)는 운행일지를 작성하지 않았습니다(국회 제출 국세청 자료). 2018년 조사에서 중소기업 72.6%가 업무용차량 규제를 가장 큰 경영 애로로 꼽았고, 2026년에도 국세청은 법인차 사적 유용에 대한 집중 세무조사를 이어가고 있습니다.

■ 현장의 불편 (이해관계자별)
- 운전자: 매 운행마다 주행 전·후 계기판 숫자를 기억해 적어야 해서 미루다가 기억에 의존해 몰아서 작성합니다. 출퇴근인지 업무인지 판단도 애매합니다.
- 공용차: 앞 사람의 "주행 후 거리"가 다음 사람의 "주행 전 거리"로 이어져야 하는데, 한 명만 빠져도 공백이 생겨 누가 탔는지 알 수 없고 세무조사 시 의심 사유가 됩니다.
- 관리자(총무·재무): 차량·운전자별 일지 취합, 누락 독촉, 엑셀 정리, 결산 시 업무사용비율 계산까지 수작업입니다. 전담 인력이 없는 소기업은 사실상 포기합니다.
- 대표·세무사: 일지를 사후에 꾸며도 검증할 수단이 없어, 제대로 쓴 기업도 소명력이 약합니다.

■ 기존 해법의 한계
스마트폰 GPS 앱은 운전자가 휴대폰과 앱을 챙겨야 하고, GPS로 추정한 거리는 서식이 요구하는 "계기판 거리"와 어긋납니다. 별도 단말기는 설치비와 월 이용료가 들고, 둘 다 공용차에서 "누가 운전했는지"를 구분하기 어렵습니다.

■ 왜 차량 안에서 풀어야 하는가
운행기록부의 핵심 값은 위치가 아니라 계기판 거리입니다. 그 값을 가진 것은 휴대폰이 아니라 차량입니다. Pleos Connect가 차량 데이터를 앱에 열면서, 처음으로 차량이 스스로 운행기록부를 쓸 수 있게 되었습니다.

## 3.
■ 핵심 기능

① 계기판 기반 자동 트립 기록
기어가 P에서 D/R로 바뀌면 운행이 시작되고, 시동을 끄면 운행이 끝납니다. 신호 대기나 잠깐 정차는 같은 운행으로 이어지고, 시동을 끄고 식사하러 가면 식당까지의 구간이 별도 운행으로 남아 개인·업무를 구분할 수 있습니다. 시작·종료 시각과 주행 전·후 계기판 거리를 Vehicle SDK의 Odometer에서 직접 읽어 저장합니다. 운전 중에는 어떤 화면도 띄우지 않고 백그라운드에서만 기록합니다.

② 공백 없는 기록 — 오도미터 체인
모든 운행은 "직전 운행의 종료 거리 = 다음 운행의 시작 거리"로 이어집니다. 앱이 기록하지 못한 주행이 있어도 계기판 거리는 줄어들지 않으므로, 다음에 차량이 켜질 때 늘어난 거리를 "미확인 구간"으로 자동 생성하고 정차 중에 운전자·용도를 지정하도록 안내합니다. 누락이 구조적으로 불가능해, 공용차 거리 공백 문제를 기술로 해결합니다.

③ 내리기 전 1탭 용도 확정
주차(P)하면 시동을 끄기 전에 거리와 출발→도착 주소, 추천 용도가 담긴 카드가 표시되고 [출퇴근] [업무] [개인] 중 하나만 누르면 됩니다. 여러 건이 쌓이면 "추천대로 모두 확정"으로 한 번에 처리합니다. 내비게이션에 저장된 집·회사 즐겨찾기와 비교해 출퇴근을 자동 추천하고, 한 번 업무로 지정한 장소는 다음부터 업무로 추천합니다. 경로 안내 중이었다면 목적지 이름(예: 거래처명)을 비고에 자동 기입합니다.

④ 운전자 본인 확인 (PIN)
시동을 걸면 운전자가 차량 화면에서 이름을 고르고 관리자가 발급한 PIN을 입력합니다. PIN은 서버에서 검증되어 체크인 기록이 남고, 그 체크인이 연결된 운행에만 "본인 확인"이 표시됩니다(5회 오류 시 잠금). 시동을 끄면 확인이 해제되어 다음 운전자는 다시 확인해야 하며, 차량 화면에는 확인된 본인의 운행만 보입니다. 공용차에서 "누가 탔는지"를 증명할 수 있고, 이전 운전자의 기록이 다음 운전자에게 노출되지 않습니다.

⑤ 국세청 양식 자동 완성
사용일자, 사용자(부서·성명), 주행 전·후 계기판 거리, 주행거리, 업무용 사용거리(출퇴근용·일반업무용), 비고를 국세청 운행기록부 서식 그대로 엑셀로 내보내고, 연간 총주행거리·업무용 사용거리·업무사용비율(법인세 신고서 별지 제29호 기재값)을 자동 계산합니다. 관리자 웹에서 차량·운전자별 일지와 미확정 건을 한 번에 관리합니다.

⑥ 개인 용도 위치 미저장 · 비용 연결
개인 용도로 확정한 운행은 주소를 지우고 거리만 남겨, 직원 감시 앱이 아닌 증빙 앱으로 설계했습니다. 내비게이션의 통행료와 차량 연비·전비로 운행별 유류·충전비를 추정해 정산에 연결합니다.

■ 차량 특화 요소 — 휴대폰으로는 할 수 없는 것
- 법정 필드를 차량이 직접 측정: 운행기록부가 요구하는 "주행 전·후 계기판 거리"를 Odometer API로 읽습니다. GPS 추정치가 아니라 계기판 실측값이라 세무 소명력이 다릅니다.
- 사람이 아니라 차에 귀속: 휴대폰·단말기·앱 실행 없이 시동만 걸면 기록됩니다. 운전자가 바뀌어도, 휴대폰을 두고 와도 빠지지 않습니다.
- 주행·정차 맥락과 결합: 기어(P/D)와 시동 상태로 운행 경계를 판단하고, 입력(PIN, 용도)은 정차 중에만 받습니다. 주행 중 운전자의 시선과 손을 쓰지 않습니다.
- 차에 붙은 본인 확인: 휴대폰 앱 설치 없이 차량 화면의 PIN으로 운전자를 확인해, 운행기록부의 "사용자" 칸에 증명력을 더합니다.
- 내비게이션과 결합: 경로를 설정하지 않은 출퇴근 주행에서도 Pleos 내비게이션에서 현재 주소를 받아 출발지·도착지를 남기고, 즐겨찾기·목적지·통행료를 용도 분류와 비용에 활용합니다.

## 4.
■ 시나리오 1. 영업팀 김 대리의 하루 (공용 법인차, 내비 미사용 출근)
- 08:10 집 앞에서 시동을 겁니다. 화면의 "운전자 확인"에서 본인 이름을 누르고 PIN 4자리를 입력합니다(본인 확인 08:10).
- 08:10~08:52 기어 D. 앱은 화면 없이 계기판 거리 12,430km를 시작값으로 기록합니다. 내비게이션은 켜지 않았습니다.
- 08:52 회사 주차장에서 P. 시동을 끄기 전 카드가 표시됩니다. "18km · ○○동 → △△동 · 추천: 출퇴근" — 집·회사 즐겨찾기와 일치해 자동 추천되었고, 김 대리는 [출퇴근]을 한 번 누른 뒤 시동을 끕니다. 운행이 끝나고 운전자 확인도 해제됩니다.
- 14:00 같은 차를 이 과장이 씁니다. 시동 후 PIN을 입력하면 이 과장 본인의 운행만 보이고, 김 대리의 기록은 보이지 않습니다. 거래처를 내비게이션 목적지로 설정해 이동하고, 도착해 P에 두면 "업무 · ○○상사 · 통행료 2,400원" 카드에서 [업무]를 누릅니다. 이 장소는 다음부터 업무로 자동 추천됩니다.

■ 시나리오 2. 기록이 빠진 주행도 공백 없이
- 오후에 다른 팀원이 차를 빌려 썼는데, 차량 시스템 재시작 등으로 앱이 그 주행을 놓쳤습니다.
- 다음 시동 때 앱은 마지막 기록(12,466km)과 현재 계기판(12,478km)의 차이를 발견하고 "기록되지 않은 12km가 있습니다" 카드를 띄웁니다. 본인이 운전한 거리라면 용도를 선택해 가져가고, 아니라면 "제가 운전하지 않았습니다"로 관리자에게 넘깁니다.
- 정차 중 운전자와 용도를 지정하면 체인이 다시 이어집니다. 연말까지 계기판 거리에 빈칸이 생기지 않습니다.

■ 시나리오 3. 월말·연말 마감 (총무 담당자)
- 관리자 웹에서 차량별 미확정 건만 골라 담당 운전자에게 알림을 보냅니다.
- 월 마감 버튼으로 국세청 서식 운행기록부를 엑셀로 내려받습니다. 결산 시에는 연간 총주행거리·업무용 사용거리·업무사용비율을 법인세 신고서(별지 제29호)에 그대로 옮겨 적습니다.
- 세무조사에서 운행기록 제출을 요구받으면 계기판 실측값이 이어진 기록을 즉시 제출합니다.

## 5.
■ 구현 형태
Pleos Connect 차량 앱(Kotlin, Android Automotive, minSdk 28 / targetSdk 34)과 관리자 웹으로 구성합니다. 차량 앱은 포그라운드 서비스로 상주하며 부팅(시동) 시 자동 시작하고, 리스너 기반으로만 동작해 폴링 없이 차량 리소스 기준(주행 중 CPU 5% 미만, RAM 400MB 이하)을 지킵니다. 화면은 정차 중에만 표시하고, portrait·landscape 멀티 윈도우에 모두 대응합니다.

■ SDK / API 사용 계획
- Pleos Vehicle SDK – Odometer (pleos.car.permission.CAR_DRIVE): getCurrentDistanceDriven / registerDistanceDriven으로 주행 전·후 계기판 거리(km). 운행기록부의 법정 필드이자 앱의 핵심 데이터
- Pleos NaviHelper SDK (pleos.car.permission.NAVI_ROUTE): getCurrentLocationInfo(출발·도착 주소, 경로 미설정 상태 포함), getBookmarkInfo(집·회사 → 출퇴근 분류), onDestinationArrived·getDestinationInfo(목적지명·통행료)
- AAOS CarPropertyManager – GEAR_SELECTION (CAR_POWERTRAIN): 기어 P→D/R 전환으로 운행 시작, P에서 정차 판단
- Android 시스템 이벤트(화면 꺼짐·종료): 3rd party 앱이 차량 시동 신호를 직접 읽을 수 없어(에뮬레이터 실측) P 상태의 화면 꺼짐·종료를 시동 끔으로 판단해 운행 종료
- 운전자 PIN 체크인: Supabase(관리자 웹 서버)의 검증 함수로 PIN을 확인하고 체크인을 발급, 운행 동기화 시 서버가 체크인 기록으로 본인 확인을 판정
- AAOS CarUxRestrictionsManager: 주행 규제 상태 확인. 입력 UI는 규제 해제(정차) 시에만 노출
- (확장) Vehicle SDK Fuel·EvBattery: 연비·전비 기반 유류·충전비 추정 / Safety: 경고등 기반 정비 알림

■ 사전 검증 완료 (Pleos Connect Emulator v2.1.0, Virtual Console)
검증용 앱을 제작해 아래 항목을 실측했습니다.
- 기어 P→D 전환 즉시 수신, 주행 규제 활성(국내 정책값) 및 P 복귀 시 해제 확인
- 오도미터 변경값 실시간 수신(약 0.1초 이내)
- 앱이 백그라운드에 있어도 기어·오도미터 이벤트 수신
- 앱을 강제 종료한 상태에서 주행한 15km를 재실행 시 "미확인 구간"으로 정확히 검출(오도미터 체인 동작 확인)
- 재부팅 후 자동 시작 확인
- 경로를 설정하지 않은 상태에서도 NaviHelper로 현재 주소 수신 확인
- P 상태에서 시동 끔(화면 꺼짐) 시 운행 즉시 종료 확인
- 실제 서버와 페어링 → 운행 동기화 → 관리자 웹 운행일지·엑셀 반영까지 확인

■ 데이터 설계
운행(시각, 운전자, 주행 전·후 계기판 거리, 용도, 주소, 목적지명, 통행료, 생성 방식[자동/미확인 구간])을 차량 내 DB에 저장하고, 확정된 운행만 서버로 동기화합니다. 차량·사용자 ID는 가명 처리하고, 개인 용도 운행의 위치는 저장하지 않습니다. 계기판 거리가 감소하는 예외(계기판 교체 등)는 체인 재시작 이벤트로 별도 기록합니다.

■ 개발 범위와 일정
- 1차 제출까지(구현 완료): 자동 운행 기록(시동 끔 기준), 오도미터 체인·미확인 구간, PIN 운전자 본인 확인, 내리기 전 1탭 용도 확정, 주소 기록, 차량 내 운행일지, 관리자 웹 연동(페어링·동기화·국세청 서식 엑셀)
- 2차 PT까지: 국세청 서식 엑셀 내보내기, 업무사용비율 자동 계산, 관리자 웹(차량·운전자별 일지, 미확정 알림, 월 마감), 개인 용도 위치 삭제, 통행료·유류비 연결
- 이후: 정비 알림, 개인사업자 모드, 세무 서비스 연동

## 6.
■ 사용자 가치
- 운전자: 기록 작업이 시동 후 PIN 입력과 운행당 1탭으로 줄어듭니다.
- 관리자: 취합·독촉·엑셀 정리가 사라지고, 결산 숫자(업무사용비율)가 자동으로 나옵니다.
- 기업: 예를 들어 관련비용 연 3,000만원(리스료 2,400만원 + 유지비 600만원)인 차량은 기록이 없으면 1,500만원만 비용으로 인정되지만, 업무사용비율 90%를 입증하면 업무사용금액 2,700만원을 기준으로 인정받을 수 있습니다(감가상각비 상당액 연 800만원 한도는 별도 적용). 계기판 실측 기록은 세무조사 소명력도 높입니다.
- 현대자동차그룹: "Pleos Connect가 있으면 법인차 세무 관리가 끝난다"는 B2B 구매 요인을 만듭니다. 법인·리스 고객에게 차량 자체가 업무 도구가 되는 경험입니다.

■ 타깃 고객
- 1차: 업무용승용차 관련비용이 연 1,500만원을 넘는 법인(리스·렌트·중형 이상 차량 보유, 공용차 운영 기업). 국내 업무용승용차 신고는 연평균 약 84만 대(2017~2021)이며, 이 중 약 40%가 운행일지를 작성하지 못하고 있습니다.
- 2차: 2026년부터 업무전용 자동차보험 의무가 확대된 복식부기의무 개인사업자, 법인 리스·렌트사(현대캐피탈 등)의 법인 고객.
- 유통: Pleos Connect가 2026년 2분기 신차부터 순차 적용되어 2030년까지 2천만 대 이상 탑재될 계획이고, 현대자동차그룹의 국내 승용차 점유율은 91.2%(2025년)로 국내 법인차 대부분이 잠재 설치 대상입니다.

■ 예상 MAU (가정 기반 추정)
가정: 국내 업무용승용차 중 현대차그룹 차량 비중 60%, 이 중 Pleos Connect 탑재 비율 2027년 5% → 2028년 15% → 2029년 30%, 탑재 차량 중 앱 도입률 20%, 차량당 운전자 1.3명.
- 2027년: 도입 차량 약 5,000대 → MAU 약 6,500명
- 2028년: 약 15,000대 → MAU 약 19,500명
- 2029년: 약 30,000대 → MAU 약 39,000명 (+ 관리자 계정)

■ Retention
운행기록은 법정 증빙이라 "쓰다 마는" 앱이 아니라, 기록이 끊기면 비용 인정이 깨지는 구조입니다. 기록 자체는 사용자 행동 없이 자동으로 이뤄지고, 사용자 행동은 운행당 1탭뿐이라 이탈 요인이 작습니다. 목표 지표는 차량 기준 월 유지율 90% 이상(연 단위 B2B 이용), 운전자 기준 주간 확정률(도착 카드 응답) 70% 이상이며, 미확정 건은 관리자 알림으로 회수합니다.

■ 수익 모델 (가안)
차량당 월 구독(B2B SaaS, 차량 대수 기준 과금) + 관리자 웹 기업 플랜. 리스·렌트사 및 세무 서비스와 제휴해 번들 판매합니다.

■ 향후 확대 계획
- 기능: 경고등·정비 상태 기반 정비 알림과 정비소 경유지 추가, 유류·충전·통행료 자동 정산, 세무사·회계 소프트웨어 연동
- 고객: 복식부기 개인사업자 단독 모드, 법인 리스·렌트사 플릿 대시보드
- 지역: Pleos Connect의 유럽 출시에 맞춰 독일 Fahrtenbuch 등 각국의 업무용 차량 운행기록 제도로 확장. 국가별 서식만 바꾸면 되는 구조로 설계합니다.
